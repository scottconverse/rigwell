# Local crash reports and bug-report ZIP

Rigwell keeps JSON crash evidence under the selected profile's `crashes/` directory. Main-process startup and uncaught errors, renderer errors/rejected promises and abnormal renderer termination, daemon startup/fatal errors and unexpected supervised daemon exits are captured locally. Intentional daemon shutdown does not create a crash report. Process capture preserves unsuccessful termination rather than trying to resume a failed process. A native fatal termination that cannot execute JavaScript is represented by its surviving supervisor where available; this does not create native memory dumps or promise capture after power loss or a fatal main-process native kill.

Reports include source, kind, time, PID, platform/runtime versions and bounded error detail. Keep the latest 50 generated regular reports; preserve unrelated files and refuse linked/nonregular paths. Reporter failures cannot replace the original failure. Renderer IPC accepts only bounded kind/detail fields from trusted app frames and permits ten reports per window per minute. It cannot select paths, sources or archive content.

Help > Report a bug opens a local ZIP save dialog. Cancel reads no credentials and writes nothing. After an explicit destination, the main process builds the archive and reports its location, included files and omissions. There is no upload, issue creation, email or external browser action. Review the ZIP before sending it wherever you choose.

The ZIP contains runtime/app versions, a coverage manifest, up to 50 crash reports and these logs when available: `main.log`, its rotated predecessor, daemon stderr/current predecessor and the existing daemon critical-error breadcrumb. Settings, credentials, sessions/transcripts, environment dumps, arbitrary log names and memory dumps are excluded. Read at most 256 KiB per source file; large text logs contribute recent complete lines, with earlier bytes explicitly omitted. Oversized single lines, malformed JSON, unavailable and linked inputs are listed as omitted. Main logs rotate around 1 MiB.

Local capture removes known secret patterns and sensitive environment values. Export additionally loads configured secret values through the existing credential resolver and removes them, including values with JSON escaping. JSON is redacted structurally before serialization. These rules cannot identify every private detail or unknown secret; do not treat redaction as permission to send an unreviewed report. Local raw daemon stderr retains its existing behavior, with redaction applied to exported contents. Zip entries use fixed safe names, stored content and platform CRC32; no archive tool, network service or extra dependency runs.

Acceptance uses temporary homes and synthetic errors only: real fatal children and daemon startup failure, headless Chromium errors/rejections through the actual main receiver, supervised daemon kill/restart, intentional shutdown, bounds/retention, secret removal, link refusal and cancelled export. Python's independent ZIP reader verified CRCs, JSON and escaped-secret redaction; a separate Node 22 fatal process verified main capture without opening Electron. Full native app/menu acceptance remains with CI and later real installed hardware checks. No real credentials, real models, visible local apps or automatic upload were used in these tests.
