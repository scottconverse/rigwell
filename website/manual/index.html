Rigwell manual · version 0.3.2

Rigwell user manual

Rigwell is a coding agent that runs on your own machine, with the model you choose. This manual covers how to install and use it, and every interface a program can call: the JSON-RPC protocol, the local HTTP and WebSocket endpoints, the CLI, the SDK and MCP.

New in 0.3.2: macOS build. New in 0.3.1: signed Windows installer. New in 0.3.0: rigwell doctor, /tree, desktop skills browser Bun + TypeScript Electron desktop app AGPL-3.0-only

One local daemon (a background process) holds the agent sessions. Four clients talk to it: a terminal UI (TUI), a desktop app, a headless exec mode and a TypeScript SDK. The agent reads, edits and runs code in your repository. Commands above the autonomy level you set wait for your approval.

What Rigwell is

A local agent harness. It talks to the model API you configure, runs tools on your machine, and keeps sessions, snapshots and settings in a folder in your home directory.

What Rigwell is not

A hosted service. It ships no model, no account and no telemetry endpoint. Hosted parts are planned, not built.

From source

You need Bun 1.4 or later, git, and rg (ripgrep) on your PATH. The Grep tool calls rg and reports an error if it is missing.

git clone https://github.com/scottconverse/rigwell
cd rigwell
bun install
bun src/cli/main.ts --help

The desktop app lives in desktop/:

cd desktop
npm install
bun run build.ts
npx electron .

To build installers: bun run package:win, package:linux or package:mac in desktop/.

Quick start

Rigwell has no built-in model list. You add each model to settings.json in the Rigwell home folder: ~/.rigwell/, or $RIGWELL_HOME if you set it.

1. Add a model

{
  "customModels": [
    {
      "model": "your-model-id",
      "displayName": "My model",
      "provider": "anthropic",
      "baseUrl": "https://api.anthropic.com",
      "apiKey": "${ANTHROPIC_API_KEY}"
    }
  ]
}

${ANTHROPIC_API_KEY} reads the key from your environment. To keep the key in the credential store, run rigwell credential set anthropic, type the key on stdin, and use "apiKey": "keychain:anthropic".

2. Start a session

rigwell                                  # terminal UI
rigwell exec --auto low "Fix the failing test"
rigwell daemon                           # background daemon for the desktop app and SDK

From source, put bun src/cli/main.ts in place of rigwell.

3. Trust the folder

The first time you open a project, Rigwell asks if you trust the folder. Project settings, hooks, skills, agents, instruction files and project MCP servers load only for a trusted folder. For scripts, use --trust or RIGWELL_TRUST_CWD=1.

Default is read-only.

A new session starts at autonomy off. The agent can read and search. Every command and edit waits for you. Raise it with --auto low|medium|high or Ctrl+L in the TUI.

Clients

All clients speak the same JSON-RPC protocol. They differ in where the session runs.

ClientStartTransportDaemon-only features
Terminal UIrigwellIn-process by default. --daemon, --socket or --url attach to a daemon.Only when attached
Desktop appThe installer, or npx electron .WebSocket to a daemon the app starts and supervisesYes

"Daemon-only" means automations, crons, missions, the side pane (files, terminals, side chat) and the Browser tool. These methods exist only on a daemon connection.

exec mode

rigwell exec prints the assistant text on stdout. It prints [session] <id> model=<m> autonomy=<a> and [turn] <reason> on stderr. The exit code is 0 only when the turn reason is completed. exec never prompts. An action that needs approval is refused.

Desktop app

The app starts its own daemon, checks it is alive, and restarts it if it stops. It adds a side pane with files, terminals, a browser pane and a side chat. It registers the rigwell:// URL scheme. Its settings live in desktop-settings.json.

Desktop features New:

  • Skills dialog. Search skills by name and description. Filter by Built-in, User or Project. Create skill writes SKILL.md to $RIGWELL_HOME/skills/<name> (user) or <project>/.rigwell/skills/<name> (project). It asks before it replaces a skill.
  • Image preview. Click an attached image, or an image in a sent message. The toolbar has zoom, Fit, Rotate, Copy, Remove and Close. Esc closes it.
  • Email drafts. A fenced email block with a To: or Subject: header shows as a card with Copy and Open in mail app (a mailto: link).

Account sign-in for models

A model can use OAuth instead of an API key. Rigwell ships no OAuth provider entries and no client ids. You register your own client and add it under oauthProviders.<name> with clientId, tokenEndpoint, and an authorizationEndpoint or deviceAuthorizationEndpoint. Then run rigwell auth login <name> (add --device for the device flow). Tokens refresh when they have less than 60 seconds left.

The auto router

With autoRouter set (a classifier model and a list of candidates), the model id auto picks a candidate for each request.

Autonomy and approvals

LevelRuns without a prompt
off (default)Reads and searches only. Edit tools are not even offered to the model. Every command asks.
lowFile edits, URL fetches, and commands the model rates low risk.
mediumAlso commands rated medium risk (reversible).
highAll commands, except those on the deny list or block list. Subagents (Task) are offered only at this level.

The model must label every Execute call with riskLevel and riskReason. A call with no risk level does not run. Rigwell then checks the command against three lists:

flowchart TD
  A["Execute call"] --> B{"riskLevel present?"}
  B -- no --> R["Not run. Model is told to resend"]
  B -- yes --> C{"On block list?"}
  C -- yes --> X["Blocked"]
  C -- no --> D{"On deny list?"}
  D -- yes --> P["Ask. No 'always' option"]
  D -- no --> E{"On allow list?"}
  E -- yes --> OK["Run"]
  E -- no --> F{"risk rank <= autonomy rank?"}
  F -- yes --> OK
  F -- no --> Q["Ask. 'Always' raises autonomy to that level"]
  • Allow list (default): ls, pwd, dir, git status, git diff, git log, git show, git blame, git ls-files.
  • Deny list (default, forces a prompt): disk format and dd to a device, shutdown and reboot, chmod -R 777 /, chown -R, Format-Volume, recursive Remove-Item -Force, rm -r on /, ~, . or $HOME, and fork bombs.
  • Block list: empty by default. A match never runs.

--skip-permissions-unsafe runs every tool call without asking. An org maxAutonomyLevel below high refuses it.

Approval prompts

A prompt offers proceed_once, proceed_always and cancel. For MCP tools it offers proceed_once, proceed_always_tools, proceed_always_server and cancel. MCP tool calls always ask unless you saved an "always" answer. Autonomy does not change that.

Command sandbox

With sandbox.enabled, Execute runs inside bubblewrap on Linux or sandbox-exec on macOS. You set file and network rules in sandbox.filesystem and sandbox.network. Windows has no sandbox. If the sandbox is on but not available, Execute fails.

Spec mode

Spec mode is read-only planning. Edits are allowed only under .rigwell/specs/. Only low-risk commands run. The model ends with ExitSpecMode, and you approve, edit, or hand the plan to a new session. Approved plans go to specSaveDir (default .rigwell/docs).

MCP servers

Rigwell is an MCP client. It connects to MCP servers and gives their tools to the model. It does not run an MCP server of its own.

mcp.json

Files: ~/.rigwell/mcp.json (user), <project>/.rigwell/mcp.json and folder .rigwell/mcp.json (trusted folders only). On a name clash the higher level wins.

{
  "mcpServers": {
    "files": { "command": "npx", "args": ["-y", "some-mcp-server"], "env": { "LOG": "1" } },
    "docs":  { "type": "http", "url": "https://mcp.example.com/mcp" },
    "old":   { "type": "sse",  "url": "https://legacy.example.com/sse",
               "headers": { "Authorization": "Bearer ${TOKEN}" } },
    "off":   { "command": "my-server", "disabled": true }
  }
}
TransportHow it works
stdioStarts the command as a child process. Newline-delimited JSON-RPC. The default when there is no url.
httpMCP streamable HTTP. POST with Accept: application/json, text/event-stream. Keeps Mcp-Session-Id. The default when there is a url.
sseLegacy SSE. GET an event stream, wait up to 10 s for the endpoint event, POST to it.

Rigwell sends MCP protocol version 2025-06-18. It uses MCP tools only. It does not use MCP resources, prompts or sampling. Servers start in parallel and never block the first turn. A dropped server reconnects after 1 s. A server that drops 6 times is marked failed.

MCP tools are deferred: the model first sees only names. It loads a schema with load_tools, then calls call_tool. In script mode it calls tools.<server>.<tool>().

Add and remove servers

  • TUI: /mcp add <name> <url|cmd>, /mcp remove <name>, /mcp to list.
  • Protocol: add_mcp_server, remove_mcp_server, list_mcp_servers. These write the user mcp.json only.
  • Per session: pass mcpServers[] to initialize_session. A session server overrides a file server with the same name.

MCP sign-in (OAuth) New in 0.2.0

An http or sse server that answers 401 needs sign-in. Rigwell shows "Sign-in needed: run rigwell mcp login <name>". Nothing opens a browser until you ask.

Terminal

rigwell mcp status
rigwell mcp login docs
rigwell mcp logout docs

Desktop app

Open the Connectors dialog (the composer chip) or Settings > Connectors. Select Sign in. The app opens your browser, waits, then reconnects the server. Sign out removes the token.

The flow follows the MCP authorization spec (2025-06-18):

sequenceDiagram
  autonumber
  participant U as You
  participant R as Rigwell
  participant M as MCP server
  participant A as Auth server
  R->>M: tools request
  M-->>R: 401 + WWW-Authenticate
  R-->>U: Sign-in needed
  U->>R: mcp login (or Sign in button)
  R->>M: GET /.well-known/oauth-protected-resource (RFC 9728)
  R->>A: GET server metadata (RFC 8414, then OpenID)
  R->>A: Register client (RFC 7591), if no client id
  R->>U: Open browser at authorize URL (PKCE S256)
  U->>A: Sign in and approve
  A-->>R: Redirect to http://127.0.0.1:port/callback
  R->>A: Exchange code (+ resource, RFC 8707)
  A-->>R: Access and refresh tokens
  R->>M: Reconnect with Bearer token

oauth options in mcp.json

"docs": {
  "type": "http",
  "url": "https://mcp.example.com/mcp",
  "oauth": {
    "scopes": ["read"],
    "clientId": "optional-preregistered-id",
    "clientMetadataUrl": "https://example.com/client.json",
    "resource": "https://mcp.example.com",
    "authorizationServerIssuer": "https://auth.example.com"
  }
}
  • Client choice: clientId, then clientMetadataUrl (if the server supports it), then a client registered before, then dynamic registration.
  • All endpoints must be https. Plain http is allowed only for 127.0.0.1 and localhost.
  • Tokens refresh before they expire. A failed refresh says "The sign-in expired".
  • Tokens are in the credential store under oauth:mcp.<server>. The client record is under mcp-oauth:<server>. Logout removes the token and keeps the client.
  • "oauth": false, or an Authorization header in headers, turns OAuth off. A 403 stays a plain error. stdio servers never use OAuth.
Tested against a fake server only.

The OAuth flow passes tests against a local fake MCP OAuth server. It is not yet tested against a real MCP server.

Automations

An automation is a saved prompt that runs on a schedule or when a local webhook is called. Automations run inside the daemon. A run is unattended: any action that would ask is refused, so the automation's autonomy decides what it can do.

  • Create one by chatting (start_automation_setup), from a template (list_automation_templates, then create_automation {templateId}), or with the TUI /automations command.
  • Template categories: health, dependencies, testing, release, git.
  • Each automation has a folder: HEARTBEAT.md (front matter and prompt), memory/, reports/, secrets.json and a generated VISUAL.html.
  • Rigwell pauses an automation by itself after missed runs or repeated failures, and sends rigwell.automation.auto_paused.

Webhook trigger

An automation with trigger: "webhook" listens on POST http://127.0.0.1:47821/hooks/<id>. The listener runs only while at least one webhook automation exists. See the webhook endpoint for the full contract.

Loops and crons

In a session, /loop 30m <prompt> repeats a prompt. Units are m and h. A loop runs only while the daemon runs and the session is open. Protocol: list_crons, create_cron, update_cron, delete_cron.

Missions

A mission is a large task that an orchestrator splits into features. Worker sessions build each feature, and validation workers check it. Missions run at autonomy high. The orchestrator proposes the mission with ProposeMission, and you approve it before StartMissionRun.

  • Protocol: enter_mission_mode, mission_get, mission_pause, kill_worker_session, mission_list.
  • Settings: missions.allowedModels, missions.orchestratorModel, and per session missionSettings (workerModel, validationWorkerModel, skipScrutiny, skipUserTesting).
  • A worker with no activity for 10 minutes stops (RIGWELL_MISSION_WORKER_INACTIVITY_TIMEOUT_MS).
  • Workstreams for missions are planned, not built.

Worktrees and pull requests

A session can run in its own git worktree (worktree: true, or the runInWorktree setting). Worktrees go to ~/.rigwell/worktrees/ unless you set worktreeDirectory. Rigwell deletes old ones when there are more than worktreeAutoDeleteLimit (default 15).

  • Git methods: list_git_branches, checkout_git_branch, git_commit, git_push, get_git_branch_divergence.
  • create_pr {title, body, base, draft} asks you first. It uses gh, or the GitHub API (RIGWELL_GITHUB_API).
  • Create PR refuses a branch with no new commits. With uncommitted edits it tells you to commit first. Fixed in 0.2.0
  • With enableSecretScan, Rigwell scans staged changes before git commit.

Eval

rigwell eval runs coding tasks against your models. It reports pass rate, cost, time, tokens, requests and cache hit rate, and compares a build with the one before.

rigwell eval tasks
rigwell eval run --model custom:My-model-0 --trials 3 --auto medium
rigwell eval report --since 7d --against <buildId>

A task is a folder evals/tasks/<name>/ with repo/, prompt.txt and task.json (a grader command and an optional budget). Shipped tasks: fix-greeting-typo, add-clamp, rename-constant. Config is ~/.rigwell/eval/config.json, with prices per million tokens and named variants. Results go to ~/.rigwell/eval/runs/<buildId>/.

JSON-RPC protocol

All clients use one protocol: JSON-RPC 2.0 with a Rigwell envelope. Protocol version: 0.1.0. It did not change in Rigwell 0.2.0, 0.3.0, 0.3.1 or 0.3.2.

{
  "jsonrpc": "2.0",
  "type": "request",            // request | response | notification (optional on input)
  "protocolVersion": "0.1.0",
  "id": "a1",                   // must be a string for requests
  "method": "rigwell.initialize_session",
  "params": { "cwd": "/path/to/repo", "machineId": "default" }
}
  • Every method name starts with rigwell.. A request without the prefix gets -32601.
  • Framing: NDJSON (one JSON object per line) on stdio and the Unix socket. One message per text frame on the WebSocket.
  • Version rule: only the major number must match. A message with no protocolVersion is accepted. A major mismatch on a request returns -32600 with both versions in data.
  • There is no separate handshake. The first call on a connection is initialize_session or load_session.
  • Client notifications are accepted and ignored. A duplicate in-flight id gets -32006.

HTTP and WebSocket paths

The daemon is not a REST server. It has no /health, /metrics or SSE route. These are all the network listeners Rigwell opens. Each binds to 127.0.0.1, except where the webhook host is changed.

Daemon WebSocket

  • Host is always 127.0.0.1. Port 47822 by default. Change it with rigwell daemon --ws-port <n> (0 = a free port) or daemon.wsPort in user settings. Turn it off with --no-ws.
  • The token is 32 random bytes, new at each daemon start. It is in ~/.rigwell/daemon.json (mode 0600) with the pid, socket path and URL.
  • Any path is accepted. One connection holds one session.
Upgrade answerCause
403 forbiddenHost header is not 127.0.0.1, localhost or [::1] (guards against DNS rebinding)

426Token OK, but the request is not a WebSocket upgrade

Daemon Unix socket

Default path ~/.rigwell/daemon.sock. If that path is longer than 103 bytes, Rigwell uses a short path in the temp folder. Change it with --socket <path>. The socket has no token. File permissions protect it.

OAuth redirect catcher

During rigwell auth login or rigwell mcp login, Rigwell opens a server on 127.0.0.1 (a free port unless redirectPort is set). It answers GET /callback once, checks state, swaps the code with PKCE S256, and stops. It times out after 5 minutes.

Desktop CDP proxy

The desktop app exposes its browser pane to the Browser tool through a small Chrome DevTools Protocol proxy on 127.0.0.1 and a random port. The daemon accepts only a ws://127.0.0.1:<port>/devtools/browser/<id> URL. This is internal to the app.

Security model

  • Loopback only. The WebSocket host is fixed to 127.0.0.1. It checks the Host header and needs a fresh token at each start.
  • Trust gate. Code-like files in a project (settings, hooks, skills, agents, instructions, MCP servers) load only after you trust the folder. A project file cannot trust itself.
  • Bounded autonomy. Default off. Commands carry a risk label. Deny and block lists. MCP tools always ask.
  • Unattended runs refuse. exec, automations and subagents with no approver refuse anything that would ask.
  • Secrets stay out of results. Auth and secret methods never return a token or a secret value.
  • Credential store. macOS Keychain or libsecret, else credentials.json with mode 0600. On Windows the code uses the file, protected by a Windows ACL (access list).
  • Sandbox. Optional on Linux and macOS. Not on Windows.
  • Webhook secret. A per-automation Bearer secret or HMAC signature.

Known limits

  • Windows is the release target. It is tested by hand on Windows only. CI runs tests on Windows, macOS and Linux.
  • No command sandbox on Windows. The sandbox is off by default on all platforms.
  • On Windows, the side-pane terminal has no PTY (a pseudo-terminal), so full-screen terminal programs do not draw correctly.
  • The installed app does not include git or rg. Grep, Glob and worktrees need them on PATH.
  • The macOS build is Apple silicon (arm64) only. It is not signed or notarized by Apple. It is built and tested in CI only. macOS blocks it the first time. To open it, run xattr -dr com.apple.quarantine /Applications/Rigwell.app in Terminal, or go to System Settings > Privacy & Security and click Open Anyway.
  • All tests use fake servers. No test calls a real model provider, OS keychain, GitHub or vendor MCP server.
  • Chrome cookie import does not work on Windows. The dialog says so when it opens.
  • MCP OAuth is tested against a local fake server only.
  • Only the Windows setup file is signed. The app inside it and the Linux files are not signed.
  • Hosted parts and Workstreams for Missions are planned, not built.
  • GitHub-event and Slack-message automation triggers are not built.
  • The SDK is not on npm.

Troubleshooting

You seeDo this
"No models configured: add customModels to settings.json"Add a customModels entry to ~/.rigwell/settings.json.
A model is missing from the listRun list_models with includeDisabled to see why. Often an unset ${VAR} or a placeholder key.
Grep failsInstall ripgrep and put rg on PATH.
Project settings or skills do not loadTrust the folder: answer yes, use --trust, or set RIGWELL_TRUST_CWD=1.
MCP server shows "Sign-in needed"Run rigwell mcp login <name>, or select Sign in in the desktop app.
"The sign-in expired"The refresh failed. Sign in again.
WebSocket gets 401 or 403Read the token from daemon.json again (it is new at each start). Connect to 127.0.0.1, not a LAN address.
The daemon has no WebSocketPort 47822 is in use. Use --ws-port 0 or set daemon.wsPort.
exec exits 1The turn did not end with completed, or an action needed approval. Raise --auto.
